Gdzie się kręciliśmy

Hasło po kicku
known_servers + learn_server_key → wycięte w J2, ale auto-relaunch został (dziura) → pin_proven_key po audycie → wycięty auto-relaunch. Zachowanie docelowe to po prostu prompt.
Konto w trakcie rankeda
cert_held_for_ranked wycięte w nocy → hold_account po audycie → wycięte.
Potwierdzenie „official”
bit official w acku + blokada rankeda wycięte w nocy → ERROR przy każdym 401 po audycie → ERROR raz na uruchomienie.
Wynik linku dla gry
tylko POST → także GET po audycie (DoS, nadpisywanie) → tylko POST + timeout w grze.
Unlink
podpisany endpoint → strona bez podpisu (K) → podpis w URL strony, ten sam schemat co link. Zostaje.
Klucze serwerów
jeden klucz → klucz na instancję (wyprowadzany) → rodzaj z konfiguracji po audycie → klucz na mecz turniejowy po audycie (401) → jeden klucz na host + etykiety.
Cache listy
cache w ścieżce łączenia → łatki 16, 17 i wyścig → cache tylko w GUI.
Hasło w trakcie czekania
ginęło → trzymane przez wait() po audycie → okienko hasła przeniesione za czekanie.

Wniosek

  • Prawie każde kółko zaczęło się od tego, że audyt zgłosił skutek wcześniejszego wycięcia, a ja przywróciłem mniejszą wersję wyciętego mechanizmu zamiast usunąć zachowanie, które go potrzebowało.
  • Dwie łatki z audytu same zrobiły nowe błędy: zapis wyniku w GET (DoS) i osobne klucze turniejowe (401).
  • Reguła na dalej: przy znalezisku najpierw pytanie, czy da się usunąć zachowanie albo przenieść je w miejsce, gdzie problem nie istnieje (hasło po czekaniu, cache tylko w GUI, etykiety zamiast kluczy).
